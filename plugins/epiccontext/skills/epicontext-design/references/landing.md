# Landing the round — step 9

A critique that lives only in the chat gets redone next quarter.

- The verdict and its findings → `write_note`, linked to the screen's
  `content_page` or `component_spec`; actionable findings become
  `create_task` cards on the board; the plan for the fixes goes out with
  `share_plan` so the team sees it beside the chat.
- A new or changed style card → `brand_asset` with its images via
  `upload_asset`.
- A reversed principle, a new deliberate-friction point, an optical
  correction, a changed stand → the project design-rules document, with a
  `reason`.
- A token the design needed but the scale lacked → a `decision` or an
  update to the fundamentals spec, never a quiet addition (the canvas's
  step 3 in `references/canvas-and-brandbook.md`).
- What is left for a person — approve a release, run the usability test,
  decide a stand — → `hand_off` to a named member.
- A pattern the suite keeps meeting — a red flag not yet in
  `references/red-flags.md`, a standard that turned out wrong, a new
  severity anchor — → `propose_skill_delta` on this skill. Skill
  knowledge is global; a platform admin reviews it.

Every write follows `epicontext-core`: read first (`get_briefing`), write
with a reason that names what you read.
