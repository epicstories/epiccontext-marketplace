# Which skill for what

Nine skills. `epicontext-core` is always relevant; load the one that matches
the work, then the reference its table points to. A path below is inside that
skill's folder: for `get_skill`, put the skill name in front
(`epicontext-groups/references/users/README`).

| Skill | Holds |
|---|---|
| `epicontext-core` | The workflow, the hard gates, the coverage mandates — always |
| `epicontext-suite` | The suite: what each tool is for, the five verbs, the organisation's shared context vs a workspace, cross-tool recipes, feature → stories and tasks as cards |
| `epicontext-context` | Making and keeping the brain right: kickoff, fill, alignment and repair, connections, the constitution |
| `epicontext-groups` | The eight groups and their entities, one reference folder per group |
| `epicontext-analysis` | Cross-group reasoning: classify a signal, recommend with trade-offs |
| `epicontext-design` | Every design judgment and design act — critique, choose, generate a screen, flow or component — with Robert's standard; the canvas, the brandbook, Figma |
| `epicontext-boards` | Workshops on Miro / FigJam boards |
| `epicontext-frontend` | Building UI in any stack; choosing a frontend framework |
| `epicontext-backend` | APIs, data, auth, server code |

## The old names

Until 21 October 2026 there were 22 skills. `get_skill` still answers the old
names with the moved content and a line naming the new place:
`epicontext-brand`, `-business-strategy`, `-users`, `-product`, `-build`,
`-marketing`, `-performance`, `-finance` and `-search-optimization` are in
`epicontext-groups`; `-kickoff`, `-fill`, `-alignment`, `-connections` and
`-constitution` in `epicontext-context`; `-development` in `epicontext-suite`;
`-framework-selection` in `epicontext-frontend`.
